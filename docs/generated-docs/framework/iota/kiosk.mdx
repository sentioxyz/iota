<Link id="iota_kiosk"/>
Kiosk is a primitive for building safe, decentralized and trustless trading
experiences. It allows storing and trading any types of assets as long as
the creator of these assets implements a <code>TransferPolicy</code> for them.


<Link id="@Principles_and_philosophy:_0"></Link>

#### Principles and philosophy:


- Kiosk provides guarantees of "true ownership"; - just like single owner
objects, assets stored in the Kiosk can only be managed by the Kiosk owner.
Only the owner can <code><Link to="../iota/kiosk#iota_kiosk_place">place</Link></code>, <code><Link to="../iota/kiosk#iota_kiosk_take">take</Link></code>, <code><Link to="../iota/kiosk#iota_kiosk_list">list</Link></code>, perform any other actions on
assets in the Kiosk.

- Kiosk aims to be generic - allowing for a small set of default behaviors
and not imposing any restrictions on how the assets can be traded. The only
default scenario is a <code><Link to="../iota/kiosk#iota_kiosk_list">list</Link></code> + <code><Link to="../iota/kiosk#iota_kiosk_purchase">purchase</Link></code> flow; any other trading logic can
be implemented on top using the <code><Link to="../iota/kiosk#iota_kiosk_list_with_purchase_cap">list_with_purchase_cap</Link></code> (and a matching
<code><Link to="../iota/kiosk#iota_kiosk_purchase_with_cap">purchase_with_cap</Link></code>) flow.

- For every transaction happening with a third party a <code>TransferRequest</code> is
created - this way creators are fully in control of the trading experience.


<Link id="@Asset_states_in_the_Kiosk:_1"></Link>

#### Asset states in the Kiosk:


- <code>placed</code> -  An asset is <code><Link to="../iota/kiosk#iota_kiosk_place">place</Link></code>d into the Kiosk and can be <code><Link to="../iota/kiosk#iota_kiosk_take">take</Link></code>n out by
the Kiosk owner; it's freely tradable and modifiable via the <code><Link to="../iota/kiosk#iota_kiosk_borrow_mut">borrow_mut</Link></code>
and <code><Link to="../iota/kiosk#iota_kiosk_borrow_val">borrow_val</Link></code> functions.

- <code>locked</code> - Similar to <code>placed</code> except that <code><Link to="../iota/kiosk#iota_kiosk_take">take</Link></code> is disabled and the only
way to move the asset out of the Kiosk is to <code><Link to="../iota/kiosk#iota_kiosk_list">list</Link></code> it or
<code><Link to="../iota/kiosk#iota_kiosk_list_with_purchase_cap">list_with_purchase_cap</Link></code> therefore performing a trade (issuing a
<code>TransferRequest</code>). The check on the <code><Link to="../iota/kiosk#iota_kiosk_lock">lock</Link></code> function makes sure that the
<code>TransferPolicy</code> exists to not lock the item in a <code><Link to="../iota/kiosk#iota_kiosk_Kiosk">Kiosk</Link></code> forever.

- <code>listed</code> - A <code><Link to="../iota/kiosk#iota_kiosk_place">place</Link></code>d or a <code><Link to="../iota/kiosk#iota_kiosk_lock">lock</Link></code>ed item can be <code><Link to="../iota/kiosk#iota_kiosk_list">list</Link></code>ed for a fixed price
allowing anyone to <code><Link to="../iota/kiosk#iota_kiosk_purchase">purchase</Link></code> it from the Kiosk. While listed, an item can
not be taken or modified. However, an immutable borrow via <code><Link to="../iota/borrow#iota_borrow">borrow</Link></code> call is
still available. The <code><Link to="../iota/kiosk#iota_kiosk_delist">delist</Link></code> function returns the asset to the previous
state.

- <code>listed_exclusively</code> - An item is listed via the <code><Link to="../iota/kiosk#iota_kiosk_list_with_purchase_cap">list_with_purchase_cap</Link></code>
function (and a <code><Link to="../iota/kiosk#iota_kiosk_PurchaseCap">PurchaseCap</Link></code> is created). While listed this way, an item
can not be <code><Link to="../iota/kiosk#iota_kiosk_delist">delist</Link></code>-ed unless a <code><Link to="../iota/kiosk#iota_kiosk_PurchaseCap">PurchaseCap</Link></code> is returned. All actions
available at this item state require a <code><Link to="../iota/kiosk#iota_kiosk_PurchaseCap">PurchaseCap</Link></code>:

1. <code><Link to="../iota/kiosk#iota_kiosk_purchase_with_cap">purchase_with_cap</Link></code> - to purchase the item for a price equal or higher
than the <code>min_price</code> set in the <code><Link to="../iota/kiosk#iota_kiosk_PurchaseCap">PurchaseCap</Link></code>.
2. <code><Link to="../iota/kiosk#iota_kiosk_return_purchase_cap">return_purchase_cap</Link></code> - to return the <code><Link to="../iota/kiosk#iota_kiosk_PurchaseCap">PurchaseCap</Link></code> and return the asset
into the previous state.

When an item is listed exclusively it cannot be modified nor taken and
losing a <code><Link to="../iota/kiosk#iota_kiosk_PurchaseCap">PurchaseCap</Link></code> would lock the item in the Kiosk forever. Therefore,
it is recommended to only use <code><Link to="../iota/kiosk#iota_kiosk_PurchaseCap">PurchaseCap</Link></code> functionality in trusted
applications and not use it for direct trading (eg sending to another
account).


<Link id="@Using_multiple_Transfer_Policies_for_different_'tracks':_2"></Link>

#### Using multiple Transfer Policies for different 'tracks':


Every <code><Link to="../iota/kiosk#iota_kiosk_purchase">purchase</Link></code> or <code>purchase_with_purchase_cap</code> creates a <code>TransferRequest</code>
hot potato which must be resolved in a matching <code>TransferPolicy</code> for the
transaction to pass. While the default scenario implies that there should be
a single <code>TransferPolicy&lt;T&gt;</code> for <code>T</code>; it is possible to have multiple, each
one having its own set of rules.


<Link id="@Examples:_3"></Link>

#### Examples:


- I create one <code>TransferPolicy</code> with "Royalty Rule" for everyone
- I create a special <code>TransferPolicy</code> for bearers of a "Club Membership"
object so they don't have to pay anything
- I create and wrap a <code>TransferPolicy</code> so that players of my game can
transfer items between <code><Link to="../iota/kiosk#iota_kiosk_Kiosk">Kiosk</Link></code>s in game without any charge (and maybe not
even paying the price with a 0 IOTA PurchaseCap)

```
Kiosk -> (Item, TransferRequest)
... TransferRequest ------> Common Transfer Policy
... TransferRequest ------> In-game Wrapped Transfer Policy
... TransferRequest ------> Club Membership Transfer Policy
```

See <code><Link to="../iota/transfer_policy#iota_transfer_policy">transfer_policy</Link></code> module for more details on how they function.

<Link id="iota_kiosk_PurchaseCap"></Link>

## Struct `PurchaseCap`

A capability which locks an item and gives a permission to
purchase it from a <code><Link to="../iota/kiosk#iota_kiosk_Kiosk">Kiosk</Link></code> for any price no less than <code>min_price</code>.

Allows exclusive listing: only bearer of the <code><Link to="../iota/kiosk#iota_kiosk_PurchaseCap">PurchaseCap</Link></code> can
purchase the asset. However, the capability should be used
carefully as losing it would lock the asset in the <code><Link to="../iota/kiosk#iota_kiosk_Kiosk">Kiosk</Link></code>.

The main application for the <code><Link to="../iota/kiosk#iota_kiosk_PurchaseCap">PurchaseCap</Link></code> is building extensions
on top of the <code><Link to="../iota/kiosk#iota_kiosk_Kiosk">Kiosk</Link></code>.


<pre>
<code>
<b>public</b> <b>struct</b> <Link to="../iota/kiosk#iota_kiosk_PurchaseCap">PurchaseCap</Link>&lt;<b>phantom</b> T: key, store&gt; <b>has</b> key, store
</code>
</pre>

## Struct `ItemPurchased`

Emitted when an item was purchased from the <code><Link to="../iota/kiosk#iota_kiosk_Kiosk">Kiosk</Link></code>. Can be used
to track finalized sales across the network. The event is emitted
in both cases: when an item is purchased via the <code><Link to="../iota/kiosk#iota_kiosk_PurchaseCap">PurchaseCap</Link></code> or
when it's purchased directly (via <code><Link to="../iota/kiosk#iota_kiosk_list">list</Link></code> + <code><Link to="../iota/kiosk#iota_kiosk_purchase">purchase</Link></code>).

The <code>price</code> is also emitted and might differ from the <code>price</code> set
in the <code><Link to="../iota/kiosk#iota_kiosk_ItemListed">ItemListed</Link></code> event. This is because the <code><Link to="../iota/kiosk#iota_kiosk_PurchaseCap">PurchaseCap</Link></code> only
sets a minimum price for the item, and the actual price is defined
by the trading module / extension.
