## Struct `Receiving`

This represents the ability to <code><Link to="../iota/transfer#iota_transfer_receive">receive</Link></code> an object of type <code>T</code>.
This type is ephemeral per-transaction and cannot be stored on-chain.
This does not represent the obligation to receive the object that it
references, but simply the ability to receive the object with object ID
<code>id</code> at version <code>version</code> if you can prove mutable access to the parent
object during the transaction.
Internals of this struct are opaque outside this module.


<pre>
<code>

## Function `transfer`

Transfer ownership of <code>obj</code> to <code>recipient</code>. <code>obj</code> must have the <code>key</code> attribute,
which (in turn) ensures that <code>obj</code> has a globally unique ID. Note that if the recipient
address represents an object ID, the <code>obj</code> sent will be inaccessible after the transfer
(though they will be retrievable at a future date once new features are added).
This function has custom rules performed by the IOTA Move bytecode verifier that ensures
that <code>T</code> is an object defined in the module where <code><Link to="../iota/transfer#iota_transfer">transfer</Link></code> is invoked. Use
<code><Link to="../iota/transfer#iota_transfer_public_transfer">public_transfer</Link></code> to transfer an object with <code>store</code> outside of its module.


<pre>
<code>
<b>public</b> <b>fun</b> <Link to="../iota/transfer#iota_transfer">transfer</Link>&lt;T: key&gt;(obj: T, recipient: <b>address</b>)
</code>

## Function `share_object`

Turn the given object into a mutable shared object that everyone can access and mutate.
This is irreversible, i.e. once an object is shared, it will stay shared forever.
Aborts with <code><Link to="../iota/transfer#iota_transfer_ESharedNonNewObject">ESharedNonNewObject</Link></code> of the object being shared was not created in this
transaction. This restriction may be relaxed in the future.
This function has custom rules performed by the IOTA Move bytecode verifier that ensures
that <code>T</code> is an object defined in the module where <code><Link to="../iota/transfer#iota_transfer_share_object">share_object</Link></code> is invoked. Use
<code><Link to="../iota/transfer#iota_transfer_public_share_object">public_share_object</Link></code> to share an object with <code>store</code> outside of its module.

## Function `receive`

Given mutable (i.e., locked) access to the <code>parent</code> and a <code><Link to="../iota/transfer#iota_transfer_Receiving">Receiving</Link></code> argument
referencing an object of type <code>T</code> owned by <code>parent</code> use the <code>to_receive</code>
argument to receive and return the referenced owned object of type <code>T</code>.
This function has custom rules performed by the IOTA Move bytecode verifier that ensures
that <code>T</code> is an object defined in the module where <code><Link to="../iota/transfer#iota_transfer_receive">receive</Link></code> is invoked. Use
<code><Link to="../iota/transfer#iota_transfer_public_receive">public_receive</Link></code> to receivne an object with <code>store</code> outside of its module.
